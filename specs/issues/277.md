# #277: Enum values differing only by punctuation generate duplicate members

Issue: https://github.com/phalt/clientele/issues/277

## Summary

Enum member names come from `utils.snake_case_prop(value.upper())`, which deletes characters that aren't valid in an identifier. `["AAA", "AA|A"]` therefore produces two members called `AAA`, and `schemas.py` fails to import (`TypeError: 'AAA' already defined`). That makes the whole client unusable.

## Root cause

`SchemasGenerator.generate_enum_properties` in `clientele/generators/shared/schemas.py` generates names without checking whether a name is already taken.

## Proposed fix

Keep the existing names, so current users see no churn, and dedupe inside `generate_enum_properties`: when a name is already taken, add `_2`, `_3`, … until it's unique. Values stay unchanged. Changing the character mapping (`|` → `_`) instead would rename existing members, which is a breaking change, so don't do that.

## Tests

In `tests/generators/api/test_issue_277.py`:

- `["AAA", "AA|A"]` generates two distinct members, the module imports, and `{m.value for m in Rating} == {"AAA", "AA|A"}`.
- Three colliding values produce `X`, `X_2`, `X_3`.
- Enums that don't collide generate exactly the same output as before (regression guard).
- A unit test on `generate_enum_properties` directly.
