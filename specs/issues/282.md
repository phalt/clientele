# #282: Option to set the base class of generated models

Issue: https://github.com/phalt/clientele/issues/282

## Summary

Generated models always subclass `pydantic.BaseModel`, so users can't apply an app-wide `model_config` (`extra="forbid"`, `frozen=True`, `alias_generator`, `json_schema_serialization_defaults_required`) without regex-rewriting `schemas.py` after every regeneration. The request is a `--base-class` option, like datamodel-code-generator's.

## Proposed fix

- Add a `start-api --base-class dotted.path.Base` option to `clientele/cli.py`, threaded through `APIGenerator` → `SchemasGenerator`.
- In `schemas_py.jinja2`, emit `from dotted.path import Base as _ClienteleBase` (or `import dotted.path`). In `schema_class.jinja2`, use it in place of `pydantic.BaseModel` for object models only. Enums, `ListResponse` and type aliases stay unchanged.
- Validate the dotted path format at the CLI (`module.attr`); don't import it at generation time.
- Persist the option in the generated `MANIFEST` so `--regen` keeps it. Check how other options are recorded.
- Watch out for interaction with the generated `model_config = pydantic.ConfigDict(populate_by_name=True, serialize_by_alias=True)` on aliased models. pydantic merges subclass config over the base config, so this should be fine; add a test.

## Tests

In `tests/generators/api/test_issue_282.py`:

- `--base-class my_pkg.models.Base` produces models whose `__mro__[1]` is `Base`, and the base's `model_config` (e.g. `extra="forbid"`) applies.
- Enums and `ListResponse` subclasses don't use the base class.
- Aliased models still serialize by alias with a custom base.
- Without the option, output is byte-identical to today (regression guard).
- An invalid dotted path gives a CLI error.
