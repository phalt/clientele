# #281: Generated Config reads unprefixed environment variables

Issue: https://github.com/phalt/clientele/issues/281

## Summary

The generated `Config` subclasses `clientele.api.BaseConfig`, which has no `env_prefix` and loads `.env` from the current directory. Every generated client reads `BASE_URL`, `TIMEOUT`, `HEADERS`, `VERIFY`, `HTTP2` and `FOLLOW_REDIRECTS`. Two clients in one app share them, and generic names like `TIMEOUT` can collide with the app's own settings.

## Root cause

`clientele/api/config.py` (`BaseConfig.model_config`) and `clientele/generators/api/templates/config_py.jinja2`, which doesn't set a prefix.

## Proposed fix

- In `config_py.jinja2`, emit `model_config = SettingsConfigDict(env_prefix="<PACKAGE_NAME>_")`, merged with the base config. `<PACKAGE_NAME>` is the upper-cased output directory name, sanitized to an identifier (e.g. `BILLING_CLIENT_`).
- Add a `start-api --env-prefix` option to override it. `--env-prefix ""` restores the current behaviour.
- Update the docstring example in the template to show the prefixed name.
- `config.py` is never overwritten on regen, so existing users aren't affected until they regenerate it themselves. Document this in the changelog and the docs.

## Tests

In `tests/generators/api/test_issue_281.py`:

- The repro from the issue: two clients (`billing_client`, `search_client`) don't share `BASE_URL`/`TIMEOUT`, and `BILLING_CLIENT_BASE_URL` configures only billing.
- `--env-prefix FOO_` produces `env_prefix="FOO_"`.
- `--env-prefix ""` reads unprefixed `BASE_URL` (backwards-compatible escape hatch).
- An existing `config.py` isn't overwritten on `--regen` (regression guard).
