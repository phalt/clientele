# #268: Fields are required when a schema has no `required` list

Issue: https://github.com/phalt/clientele/issues/268

## Summary

In OpenAPI, a property is required only if it appears in its schema's `required` array. When a schema has no `required` array, or an empty one, every property is optional. The generator does the opposite: those schemas come out with every property required. The report has an `UpdateParams` with no `required` list that generates `name: str`, so callers can't do a partial update without supplying `name`.

## Root cause

`clientele/generators/shared/schemas.py`, `SchemasGenerator.generate_class_properties`:

```python
is_optional = required and arg not in required
```

When `required` is `None` or `[]`, the expression is falsy, so the property is treated as required.

## Proposed fix

```python
is_optional = arg not in (required or [])
```

Properties that aren't listed become `typing.Optional[T] = None`, matching what already happens to schemas that do have a `required` list. Nothing else changes for properties that have a `default` or are already nullable.

The "key omitted vs key sent as `null`" question raised in the issue is handled by #276 and the current `exclude_unset=True` behaviour. It is out of scope here.

## Tests

In `tests/generators/api/test_issue_268.py`:

- A schema with no `required` key generates every property as `typing.Optional[...] = None`, and the model validates `{}`.
- A schema with `required: []` behaves the same way.
- A schema with `required: ["name"]` keeps `name` required and makes the other properties optional (regression guard).
- A request body schema (`generate_input_class`) with no `required` list generates optional properties.
- `allOf` parts with no `required` list generate optional properties.
