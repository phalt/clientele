# #279: Use the bundled ruff instead of the one on PATH

Issue: https://github.com/phalt/clientele/issues/279

## Summary

`ClienteleAPIGenerator.format_client` runs `["ruff", ...]`, which uses whatever `ruff` is first on `PATH`. If the venv isn't activated (`.venv/bin/python -m clientele.cli`, or a call through `subprocess`), formatting is silently skipped. The same spec and version then produce different output, which causes spurious CI diffs. `ruff check --fix` also rewrites code (`Optional[X]` → `X | None`, unused imports), so the difference isn't only cosmetic.

## Root cause

`clientele/generators/api/generator.py`, `format_client` (~lines 129/136).

## Proposed fix

Resolve the ruff binary once:

1. `ruff.find_ruff_bin()` if `ruff` is importable (it's a `clientele[cli]` dependency).
2. Otherwise `shutil.which("ruff")`.
3. Otherwise keep the current warning and skip.

Use the resolved path for both the `format` and the `check --fix` calls. Check the basic generator for the same pattern and fix it too.

## Tests

In `tests/generators/api/test_issue_279.py`:

- With `PATH` stripped of ruff (monkeypatch `PATH` to `/usr/bin:/bin`), generated output is formatted and identical to output generated with ruff on `PATH`.
- Unit test: the resolver prefers `find_ruff_bin`, falls back to `which`, and returns `None` when neither works (mock both). `format_client` logs the warning and doesn't raise.
